Bouncer System starts new users as **Unverified** and lets designated **Security** users grant access from the player list or scanner.

## Role hierarchy

Higher roles inherit the access of the roles below them.

| Level | Role | Access |
| ---: | --- | --- |
| `0` | Unverified | No Bouncer-managed access. |
| `1` | Verified | Verified objects and areas. |
| `2` | VIP | Verified access plus VIP objects and areas. |
| `3` | Temporary Security | Verified, VIP, and Security access until the player leaves, unless Persistent Roles is enabled. |
| `4+` | Automatic Security | Full access, cannot be removed manually. Can assign and remove temporary security access.

## Change another player's role

1. Join as a Security user.
2. Find the player in the Bouncer System panel.
3. Use the **Verified**, **VIP**, or **Security** toggle beside their name.
4. Wait for the checkmark to update across clients.

:::note
You need to remove the highest role first before you can remove a lower role. For example, you must remove VIP before you can remove Verified. You cannot change your own roles.
:::

## Verify with a scanner

Security users can pick up a configured scanner and press trigger in VR or left click on Desktop. The scanner verifies the nearest eligible player within its configured distance.

- **Green:** a player was verified successfully.
- **Red:** no eligible player was found within range.

The scanner cannot unverify players and does not replace VIP or Security roles.

:::tip
Change the scanner's `MAX_DISTANCE` value if you find it hard to select users.
:::

## Automatic roles

Automatic role sources are configured in the Inspector. Higher roles take priority over lower roles.

Remote lists load asynchronously. The configured loading screen stays visible until every configured list finishes or fails.

You can use the **Refresh Button** to reload your roles.

## Persistent Roles

Enable `PersistentRoles` to restore given roles when a player leaves and rejoins the **same live instance**. The feature does not transfer roles to a different world instance.

For Udon integrations, see the [API reference](./api).
